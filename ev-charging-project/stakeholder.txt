1. EXECUTIVE SUMMARY & VALUE PROPOSITION
--------------------------------------------------------------------------------
Electric vehicle (EV) adoption in India faces major adoption barriers known as 
"Range Anxiety" and "Charging Anxiety". EV drivers frequently encounter:
1. Broken, malfunctioning, or offline chargers.
2. Long, unpredictable queues with no occupancy visibility.
3. Chargers with incompatible connectors or inadequate power output.
4. Battery depletion on routes where actual consumption exceeds nominal vehicle range 
   due to traffic, topography, climate control, and aggressive driving.

This project delivers a production-grade, end-to-end Intelligent EV Charging and 
Navigation Platform designed for the Indian EV ecosystem (seeded with 382 real 
commercial stations across Karnataka). 

The platform unites:
- Multi-criteria machine learning models for charger reliability, occupancy forecasting, 
  and user review sentiment analysis.
- An intelligent recommendation engine that ranks stations based on user preferences, 
  predicted wait times, pricing, and failure probabilities.
- A virtual vehicle telemetry and Virtual OBD-II provider that emulates real EV data.
- Interactive map-based route planning, road routing, and destination battery feasibility.
- A synthetic data collection pipeline and machine learning models (Linear Regression 
  and XGBoost) for predicting trip-level energy consumption.
- An OCPP 1.6-J IoT testbed for protocol-level charger communication.

2. COMPLETE TECHNOLOGY STACK
--------------------------------------------------------------------------------
The project utilizes a modern, resilient, decoupled micro-architecture:

A. BACKEND & API LAYER
   - Language: Python 3.10+
   - Web Framework: FastAPI (high-performance asynchronous web framework)
   - ASGI Server: Uvicorn (with hot reload enabled)
   - Data Validation: Pydantic schemas (strict type validation and contract safety)
   - ORM / Database Toolkit: SQLAlchemy 2.0
   - Routing Services: OSRM (Open Source Routing Machine) integration & Haversine geo-algorithms

B. DATABASE & STORAGE
   - Relational Database: PostgreSQL 15
   - Containerization: Docker & Docker Compose
   - Automated Data Seeding: Auto-initializes on startup with:
     * 382 Karnataka commercial charging stations (scraped from Open Charge Map)
     * 34,000+ historical charging session logs
     * 7,000+ user review and sentiment entries
     * Comprehensive charger hardware fault records

C. MACHINE LEARNING & DATA PIPELINE
   - Core ML Libraries: Scikit-Learn, XGBoost, SciPy, NumPy, Pandas
   - Natural Language Processing (NLP): NLTK, TextBlob, VADER sentiment analyzer
   - Model Serialization: Joblib (persisting trained models and full preprocessing pipelines)
   - Feature Engineering: Scikit-Learn ColumnTransformer, StandardScaler, OneHotEncoder

D. FRONTEND & VISUALIZATION DASHBOARD
   - Core Framework: React 18 with Vite (rapid HMR and optimized bundling)
   - Styling: Tailwind CSS & Vanilla CSS (sleek dark mode, responsive glassmorphism)
   - Geospatial & Maps: Leaflet & React-Leaflet (custom vehicle pins, destination flags, 
     clustered charger markers, and dual-layer interactive road polylines)
   - Icons: Lucide React
   - HTTP Client: Axios (REST API communication with FastAPI backend)

E. HARDWARE & IOT PROTOCOL TESTBED
   - Protocol: OCPP 1.6-J (Open Charge Point Protocol JSON over WebSockets)
   - Hardware Target: ESP32 microcontroller / Raspberry Pi firmware client
   - Central System: Python-based WebSocket server simulating EVSE (EV Supply Equipment)

3. WHAT THE SYSTEM DOES (CORE SYSTEM MODULES)
--------------------------------------------------------------------------------

MODULE 1: CHARGER RELIABILITY PREDICTION
- Problem: EV drivers arrive at chargers only to discover they are broken or offline.
- Solution: A Random Forest / XGBoost model trained on historical fault reports, uptime 
  records, session completion ratios, and review sentiment.
- Output: A continuous reliability score (0.0 to 1.0) indicating the statistical 
  probability that a station will successfully charge the vehicle.

MODULE 2: OCCUPANCY & WAIT-TIME FORECASTING
- Problem: Inability to predict whether a station will have available plugs upon arrival.
- Solution: A predictive model that factors in time-of-day, day-of-week, station power rating, 
  and historical usage patterns.
- Output: Current occupancy probability and estimated waiting time in minutes.

MODULE 3: MULTI-CRITERIA RECOMMENDATION ENGINE
- Evaluates all stations within a customizable search radius (e.g., 25 km).
- Filters by connector compatibility (e.g., CCS2, Type 2, CHAdeMO) and vehicle capacity.
- Scores and ranks stations using an intelligent multi-attribute utility formula:
  * Travel distance / time
  * Predicted reliability score
  * Estimated wait time
  * Charging speed / power output (kW)
  * Tariff / pricing per kWh

MODULE 4: VIRTUAL EV TELEMETRY & VIRTUAL OBD PROVIDER
- Eliminates the need for expensive physical EV hardware during development while 
  providing an authentic software test vehicle.
- Produces a standard 13-field telemetry stream:
  * Vehicle ID, Timestamp, Latitude, Longitude, Speed (km/h)
  * Battery Capacity (kWh), Current SoC (%), Remaining Energy (kWh)
  * Cumulative Energy Consumed (kWh), Estimated Range (km)
  * Vehicle Status (Standby, Driving, Paused, Destination Reached)
  * Data Source & Connection Status
- Live GPS Initialization: Requests browser/device GPS on mount; gracefully falls back 
  to predefined Mysore coordinates if permission is denied.
- Virtual OBD Provider Abstraction: Decouples the telemetry source from React state, 
  establishing an exact drop-in replacement point for real Bluetooth/OBD hardware.

MODULE 5: INTERACTIVE TRIP PLANNING & ROAD ROUTING
- Map-Based Destination Selection: Click anywhere on the Leaflet map to set or modify 
  a driving destination (marked by an animated 🏁 pin).
- Real Road Route Generation: Calls the backend `/route` endpoint (OSRM) to generate 
  true road geometry, route distance (km), and estimated travel time (min).
- Visual Road Polyline: Renders a dual-layer road polyline (deep violet casing + vibrant violet core).

MODULE 6: DETERMINISTIC DESTINATION FEASIBILITY ANALYSIS
- Baseline physics calculation: `estimated_trip_energy_kwh = route_distance_km * 0.150 kWh/km`.
- Dynamic comparison against `telemetry.remaining_energy_kwh`.
- Real-time feasibility badge:
  * "Destination Reachable" (emerald) when battery is sufficient.
  * "Charging Required" (amber) when trip energy exceeds available battery.
- Dynamically updates as the simulated vehicle drives and drains its battery.

MODULE 7: SIMULATION CONTROLS & LIFECYCLE
- Interactive controller with complete state machine:
  * [ Start Drive ]: Moves the vehicle along the road route, draining energy at 0.150 kWh/km.
  * [ Pause ]: Freezes motion, zeroes speed, stops battery drain, preserves coordinates.
  * [ Resume ]: Continues driving from exact paused progress.
  * [ Reset ]: Restores vehicle to its captured initial baseline (initial coordinates, 
    initial 20% SoC, 6.0 kWh remaining, 0 consumed) without clearing the destination.

MODULE 8: DATA COLLECTION PIPELINE & ML ENERGY PREDICTION
- Frontend Trip Recorder: Silently records intermediate telemetry points during simulated 
  drives and aggregates completed trip features; discards incomplete trips on reset.
- Synthetic Dataset Generator (`pipeline/generate_energy_dataset.py`):
  * Generates 1,200 reproducible trip samples (seed=42) across 11 input features.
  * Introduces controlled physical variations: aerodynamic drag at higher speeds, 
    elevation potential energy (ascent drain / descent regen), traffic congestion friction, 
    HVAC cooling draw above 25°C, and driving styles (Eco, Normal, Aggressive).
- Data Dictionary (`ENERGY_CONSUMPTION_DATA_DICTIONARY.md`): Full documentation of every column.
- Model 1: Baseline Linear Regression (`models/energy_regression_model.py`):
  * Pipeline: StandardScaler + OneHotEncoder + LinearRegression
  * Test Metrics: MAE = 0.1862 kWh, RMSE = 0.2860 kWh, R² = 0.9914
- Model 2: XGBoost Regressor (`models/energy_xgboost_model.py`):
  * Pipeline: OneHotEncoder + Passthrough + XGBRegressor
  * Test Metrics: MAE = 0.1302 kWh, RMSE = 0.2110 kWh, R² = 0.9953 (30.1% MAE reduction)
  * Feature Importances: Distance (66.0%), Duration (27.9%), Elevation (1.5%), Style (1.1%).
